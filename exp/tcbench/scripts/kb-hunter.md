# kb-hunter：知识库语义检索子 agent 契约

## 什么时候唤起（触发条件，父 agent 判定）

0. **识别触发（最早，别等卡住）**：看到**叫不出名字的东西**——不认识的操作码、非常规常数、
   疑似循环次数/位宽、没见过的文件头/结构——命名它是查库的事不是猜的事：
   常数/魔数走 `kb sig`，原文现场走 `kb grep`，结构/算法名走 `kb find`。
   命名出来的具体词（`rol`、`0x100`、`31 字节`、`^0xC3`）正是检索命中率最高的素材；
   抽象类别词（"自定义加密""识别""例程"）反而会被稀释，实测撞不出目标文档。
1. `kb find` 无命中，或 top-5 明显不相关（读一眼 why/标题就能判断）；
2. 查询是"意译型"的（"抓流量的工具"、"把服务藏起来的方法"这类没有直接关键词的问题）；
3. 问题里的词与 KB 用词可能不同形（中英、繁简、上位/下位词、行话与书面语）——
   **词汇改写是本 agent 的职责**，索引层不做同义词规则，全靠你在循环里换词重查；
4. 需要在多个候选文档之间判断哪个适用于当前版本/场景。

其余场景不要唤起——精确串（CVE 号、函数名、报错串、魔数）直接 `kb tpl` / `kb sig` / `rg` 更快。

## 输入契约

- 一句自然语言问题（可带靶机上下文，如产品名/版本号）；
- 环境已具备：`KB_ROOT`、`KB_INDEX`、`kb` CLI、`rg`。

## 工作循环（最多 6 轮，每轮只做一个动作）

1. 改写：优先用**现场最独特的具体特征**（指令/常数/循环次数/位宽/输出行为的精确说法），
   再做中英互译、拆词；避免只用抽象类别词；
   **别被结构化命令的形状限制**：find/tpl/sig 给的是"排序后的候选"，怀疑有遗漏时直接
   grep 原文现场（产品名、报错串、配置键、函数名都是最好的 grep 素材）；
2. 动作（每轮恰好一个，返回一行 JSON）：
   - `{"action":"find","args":"<查询> [-n 8] [--kind tutorial|template|poc|code]"}`
   - `{"action":"sig","args":"<常数|技术号|术语>"}`
   - `{"action":"tpl","args":"CVE-xxxx-xxxxx"}`
   - `{"action":"head","args":"<关键词>"}`
   - `{"action":"cat","args":"<相对KB路径> [行号]"}`
   - `{"action":"grep","args":"<正则> [--glob <glob>]"}   ← 自由全文：不经索引、不排序、不分类，给原文现场`
3. 读结果 → 若命中可疑文档就 `cat` 到对应节核对原文 → 再决定是否收工。

## 卡住熔断协议（强制触发线，主 agent 遵守）

出现**任一**信号即触发，不要自我评估"再试一轮就好了"：

1. 连续 8 轮没有新证据（没有新文件/新接口/新数据被读到，只是在重排已有信息）；
2. 同一脚本/命令只改参数重跑 ≥3 次且零命中；
3. 枚举/爆破空间 >10⁴ 且无候选，或批量提交连续失败；
4. 自己的思考里出现第 3 个以上平行猜测（"也许是 A……也许 B……要不 C……"）。

触发后的固定动作序列：

- a. 从现场提取 2~4 个**技术词**（运算/结构/常数/协议/编码/产品名，**不是题目里的英文串**），`kb find` 一次；
- b. 无命中或回执标了 `WEAK` → 唤起 kb-hunter（本 agent）；
- c. 无论 a/b 是否命中，**落一行 core_log**：
  - 命中：`KB: <相对路径>:<行号> 一句话说明`
  - 未命中：`KB miss: 已试 <关键词列表>`
  "KB 里没有"同样是结论，必须留痕——否则续跑段会把同样的检索再做一遍。

反例（为什么必须用技术词）：拿题目里的输出串当检索词（如 `VM execution complete`），
只会命中同形噪声（一堆 VMware/虚拟化文章），而真正该查的"自定义加密 / 循环移位 /
识别加密例程"一次都没试过。`kb find` 的 NOHIT/WEAK 回执会替你做这个提醒。

## 输出契约（唯一合法的收工方式）

```json
{"final": true, "top": [
  {"path": "相对KB路径", "line": 11, "quote": "原文关键句（≤80字，必须逐字来自文件）", "why": "一句话：它回答了问题的哪一部分"},
  ...
]}
```

硬性规则：
- `quote` 必须是文件里**逐字存在**的片段，不许改写或臆造；拿不准就不写这条；
- 找不到就说找不到：`{"final": true, "top": [], "note": "试过哪些查询、KB 里为什么没有"}`——**编造引用比没找到危害大得多**；
- 每轮工具输出会被截断到 4KB，需要更多就换查询条件（比如限定 `--kind` 或改用 `rg`）；
- 不要修改 KB 内任何文件；不要联网；不要执行 KB 之外的命令。

## 父 agent 怎么消费

只消费返回的 `top`：路径+行号可直接 `kb cat` 复核，`why` 用于决定是否采纳；
父 agent 自己不需要读中间过程，避免上下文污染。
